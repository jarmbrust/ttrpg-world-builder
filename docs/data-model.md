# Data Model

## 1. Prisma schema (conceptual)

> Auth tables (`User`, `Session`, `Account`, `Verification`) are generated by **Better Auth** and
> merged into the Prisma schema (`npx @better-auth/cli generate`). `User` is extended with `role`
> and `readOnly`.
> The generator/provider block should follow Prisma 7's current docs at implementation time.

```prisma
enum Role {
  PLAYER
  GM
}

enum ArticleType {
  WORLD      // world overview & cosmology
  LOCATION   // regions & locations
  FACTION    // factions & organizations
  NPC        // npcs
  DEITY      // pantheon, gods & religion
  HISTORY    // history & timeline
  HOUSE_RULE // house rules & homebrew
  RECAP      // session recaps / adventure log
  CHARACTER  // player characters (GM-authored intro; linked to Character record)
}

enum Tier {
  PUBLIC   // everyone (no login)
  PLAYER   // logged-in players and above
  GM       // full GM (admin) and read-only GM only
}

enum ArticleStatus {
  DRAFT
  PUBLISHED
}

// --- Better Auth (extended) ---

model User {
  id            String    @id
  name          String
  email         String    @unique
  emailVerified Boolean   @default(false)
  image         String?
  role          Role      @default(PLAYER)
  readOnly      Boolean   @default(false) // guest mode (admin-toggled)
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt

  character     Character?
  authored      Article[]  @relation("ArticleAuthor")
  edited        Article[]  @relation("ArticleEditor")
  uploads       Image[]
}

// --- Domain ---

model Article {
  id           String        @id @default(cuid())
  slug         String        @unique
  title        String
  excerpt      String?
  body         String        // Markdown
  type         ArticleType
  tier         Tier          @default(GM)
  status       ArticleStatus @default(DRAFT)
  order        Int           @default(0)

  parentId     String?
  parent       Article?      @relation("ArticleTree", fields: [parentId], references: [id])
  children     Article[]     @relation("ArticleTree")

  tags         Tag[]
  links        ArticleLink[] @relation("ArticleSource")
  linkedBy     ArticleLink[] @relation("ArticleTarget")

  coverImageId String?
  coverImage   Image?        @relation("ArticleCover", fields: [coverImageId], references: [id])

  revealedAt   DateTime?
  createdById  String
  createdBy    User          @relation("ArticleAuthor", fields: [createdById], references: [id])
  updatedById  String?
  updatedBy    User?         @relation("ArticleEditor", fields: [updatedById], references: [id])
  createdAt    DateTime      @default(now())
  updatedAt    DateTime      @updatedAt

  @@index([type, tier])
  @@index([type, order])
}

// Explicit join for wiki-style cross-links (allows a future link label).
model ArticleLink {
  articleId String
  relatedId String
  article   Article @relation("ArticleSource", fields: [articleId], references: [id])
  related   Article @relation("ArticleTarget", fields: [relatedId], references: [id])

  @@id([articleId, relatedId])
}

model Tag {
  id       String    @id @default(cuid())
  name     String    @unique
  articles Article[]
}

model Character {
  id              String   @id @default(cuid())
  userId          String   @unique
  user            User     @relation(fields: [userId], references: [id])

  name            String   // character name
  class           String
  ancestry        String
  background      String

  portraitImageId String?
  portrait        Image?   @relation("CharacterPortrait", fields: [portraitImageId], references: [id])

  updates         CharacterUpdate[]
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}

// Short status entries the player appends (e.g. "Gained 5th level", "Slew the Jabberwocky").
model CharacterUpdate {
  id          String    @id @default(cuid())
  characterId String
  character   Character @relation(fields: [characterId], references: [id])
  text        String
  createdAt   DateTime  @default(now())
}

model Image {
  id           String   @id @default(cuid())
  publicId     String   @unique // Cloudinary public id
  altText      String?
  tier         Tier     @default(GM) // mirrors article reveal model
  uploadedById String
  uploadedBy   User     @relation(fields: [uploadedById], references: [id])
  createdAt    DateTime @default(now())

  articles     Article[] @relation("ArticleCover")
  characters   Character[] @relation("CharacterPortrait")
}
```

## 2. Content types → sections

The `ArticleType` enum maps 1:1 to the player-facing navigation sections:

| Section | `type` | Index route | Article route |
|---|---|---|---|
| World overview & cosmology | `WORLD` | `/world` | `/wiki/[slug]` |
| Regions & locations | `LOCATION` | `/locations` | `/wiki/[slug]` |
| Factions & organizations | `FACTION` | `/factions` | `/wiki/[slug]` |
| NPCs | `NPC` | `/npcs` | `/wiki/[slug]` |
| Pantheon, gods & religion | `DEITY` | `/pantheon` | `/wiki/[slug]` |
| History & timeline | `HISTORY` | `/history` | `/wiki/[slug]` |
| House rules & homebrew | `HOUSE_RULE` | `/house-rules` | `/wiki/[slug]` |
| Session recaps / adventure log | `RECAP` | `/recaps` | `/wiki/[slug]` |
| Player characters | `CHARACTER` | `/characters` | `/wiki/[slug]` (+ edit form) |
| Maps | *(images)* | `/maps` | — |

All articles share a single canonical `/wiki/[slug]` route (slugs are unique), which makes
cross-linking stable regardless of section. Section index pages are filtered lists of
`Article` by `type`.

## 4. Data flow notes

- **Read:** Server Component → `verifySession()` → Prisma query filtered by the viewer's readable
  tiers (read scope is role-driven; `readOnly` does not change it) → render Markdown with
  cross-link resolution.
- **Write (GM):** Server Action → `authorize({ write: true })` (role `GM` and `readOnly: false`) →
  upsert `Article` → (on reveal) set `tier = PLAYER` and `revealedAt = now()`, then
  `revalidateTag('article:<slug>')`.
- **Player character edit:** Server Action → `authorize({ write: true })` → assert the target
  `Character.userId === session.userId` (or role `GM`) → update fields / append `CharacterUpdate`.
- **Images:** upload → Cloudinary (signed upload) → store `publicId` + `tier` → serve via
  `GET /api/images/[id]` which checks the viewer's tier and returns a short-lived signed URL.

## 5. Access-control summary

See [Architecture §4](architecture.md#4-access-control-model) for the full permission matrix.

The permission logic depends on just three fields — `User.role`, `User.readOnly`, and the `tier`
on `Article`/`Image` — and lives in a single `authorize()` module:

- **Read scope** is determined by `role` only (anon → `public`; `PLAYER` → `public`+`player`;
  `GM` → all tiers).
- **Write access** requires `readOnly: false` **and** the role's write capability. `readOnly`
  blocks every mutation (including reveal and account management).
- **Account types are derived** (`role` × `readOnly`): GM = `{GM, false}` (admin), Player =
  `{PLAYER, false}`, Guest-Player = `{PLAYER, true}`, Guest-GM = `{GM, true}`.
- **Future:** a global `hideGmSecretsFromGuests` setting (admin-toggled) would, when enabled, drop
  Guest-GM read scope from `gm` to `player`; implement it inside `authorize()` so no other code
  changes.
